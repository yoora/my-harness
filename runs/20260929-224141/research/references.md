# 경쟁 서비스 레퍼런스

조사일: 2026-09-29. 공식 도움말 텍스트를 조사했다. 스크린샷을 직접 관찰했다고 주장하지 않는다.

대상: S1 내 자산 목록 / S2 자산 등록 / S3 자산 상세·신청 상태 / S4 운영자 검수 목록 / S5 운영자 검수 상세.

## R1 · Notion Marketplace

[공식 출처](https://www.notion.com/help/selling-on-marketplace)

- 관찰: 이름·링크·분류·언어·설명을 입력하고 저장 또는 검수 제출을 구분한다. 창작자 대시보드에서 제출 상태를 확인하고 수정·재제출할 수 있다.
- 근거 수준: 공식 도움말 본문
- 연결 화면: S1, S2, S3, S4
- 반영: S1 상태 표시, S2 저장과 신청 분리, S3 검수 상태. S4는 동일 상태 체계를 운영자 목록으로 확장한 PRD 기반 추론이며 Notion 내부 운영자 UI를 관찰한 것이 아니다.

## R2 · Notion Marketplace

[공식 출처](https://www.notion.com/help/getting-featured-in-the-template-gallery)

- 관찰: 선정 기준을 가치·구현 품질·사용 안내·시각 디자인·썸네일 등으로 나누어 설명한다.
- 근거 수준: 공식 도움말 본문
- 연결 화면: S5
- 반영: S5 검토 항목을 명시하는 패턴만 참고. 허들링 필수 체크리스트는 PRD를 따른다. 실제 Notion 운영자 검수 화면은 확인하지 않았다.

## R3 · Gumroad

[공식 출처](https://gumroad.com/help/article/247-what-your-customers-see)

- 관찰: 구매자는 라이브러리에서 상품 타일을 선택해 해당 상품 콘텐츠로 들어간다.
- 근거 수준: 공식 도움말의 검색 인덱스 발췌; 직접 open 본문은 비어 있음
- 연결 화면: S1, S3
- 반영: 목록에서 개별 자산 상세로 진입하는 정보 구조 참고. 구매자 라이브러리와 창작자 내 자산의 권한은 다르다.

## R4 · Gumroad

[공식 출처](https://gumroad.com/help/article/126-setting-up-versions-on-a-digital-product)

- 관찰: 상품 버전에 이름·설명 등을 입력하며 콘텐츠 탭에서 파일·영상·글을 추가한다.
- 근거 수준: 공식 도움말의 검색 인덱스 본문; 직접 open 본문은 비어 있음
- 연결 화면: S2, S3
- 반영: 자산 설명과 실제 파일 구성을 구분해 보여준다. 버전 판매·가격 추가 기능은 이번 허들링 화면에 도입하지 않는다.

## R5 · Framer Marketplace

[공식 출처](https://www.framer.com/help/articles/how-to-publish-a-template/)

- 관찰: 이름·설명·이미지·분류·미리보기 URL 등을 입력하고 공개 후 수정할 수 있다. 2026-09-15 갱신 문서는 제출 즉시 공개되며 사전 승인 과정이 없다고 명시한다.
- 근거 수준: 공식 도움말 본문
- 연결 화면: S2, S3
- 반영: 메타데이터와 미리보기 구성 참고. 즉시 공개는 허들링 금지 조건과 충돌하므로 채택하지 않는다.

## R6 · Framer Marketplace

[공식 출처](https://www.framer.com/help/articles/template-best-practices/)

- 관찰: 독창성·디자인·레이아웃·텍스트·반응형 등으로 품질 점검을 나눈다. 수동 검수의 필수 요건이 아니라 제작자 권장 사항이라고 명시한다.
- 근거 수준: 공식 도움말 본문
- 연결 화면: S4, S5
- 반영: 검수 상세의 항목별 근거 구조와 목록의 점검 요약에 참고. 운영자 목록·승인 UI 자체는 PRD 기반 추론이다.

## 공통 패턴

- **P1** 자산 등록 시 이름·설명 등 메타데이터와 파일/미리보기 내용을 명시적으로 구성한다. 근거: R1, R4, R5.
- **P2** 여러 자산의 목록/대시보드에서 개별 자산의 상세 또는 편집으로 진입한다. Notion은 창작자, Gumroad Library는 구매자 맥락이므로 역할은 그대로 복제하지 않는다. 근거: R1, R3.
- **P3** 품질을 추상적 좋음이 아니라 설명·사용성·시각 구성 등 여러 검토 항목으로 나누어 점검한다. 승인 강제 여부는 서비스마다 다르다. 근거: R2, R6.

## 해석의 한계

- 공식 도움말의 텍스트 기반 조사이며 로그인된 제품 화면이나 스크린샷을 직접 확인하지 않았다.
- S4·S5 운영자 UI는 PRD 기반 추론이다. 공개된 경쟁사 내부 운영자 화면 증거가 아니다.
- Gumroad 두 문서는 공식 페이지 검색 인덱스 내용을 확인했고 직접 열기에서는 본문을 얻지 못했다.

## 서비스 기준 우선

허들링 자산은 기본 비공개다. 저장, 명시적 판매 신청, 운영자 검수를 분리한다. 경쟁사의 공개·판매·결제 기능을 근거로 MVP 범위를 넓히지 않는다. S4·S5의 필수 체크리스트와 승인·수정 요청·반려는 경쟁사 UI 복제가 아닌 허들링 PRD 요구다.
